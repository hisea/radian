# radian 0.2.0

This release adds arc, a plan and task orchestrator built into the `radian`
binary, as a command-line preview. It also fixes `git commit` inside the
Linux sandbox, lets an MCP server set its working directory, and makes `!`
commands follow the same trust rule as the `shell` tool.

## arc (preview)

arc keeps a plan and its tasks as files in the repository, runs each task as
a separate headless `radian` worker in its own worktree, and merges only what
passes a gate.

- `radian arc init` sets arc up for a repository. `add`, `list`, `show` and
  `adopt` write and read plans and tasks; `confirm`, `auto` and `pause`
  control a plan.
- `radian arc start`, `cancel` and `reset-budget` run and stop one attempt.
  An attempt has retries with backoff, stall and wall-time limits, and
  per-attempt cost and budgets.
- A finished attempt goes through the gate: the stages a profile lists, then
  an integration run at merge. `radian arc merge` needs your approval bound
  to the commit and the gate result, and pushes without force.
  `radian arc reject` sends a task back with a note.
- `radian arc run` is the scheduling loop. The auto levels `off`, `run` and
  `merge` decide how far it goes without you; `max_auto_rework` pauses a plan
  that keeps failing.
- `radian arc mcp` is an MCP server with six tools that a lead session uses to
  write plans and tasks. None of them approves a merge.
- The arc terminal interface is not built yet: a bare `radian arc` says so,
  lists the subcommands and exits `2`.
- **Before you run arc unattended on macOS**, use an ssh remote. The
  `workspace` sandbox hides `~/.ssh`, but it does not block the keychain, so a
  worker can get an https credential that the keychain holds.

`docs/user/arc/index.md` (or `radian docs arc`) is the full reference: every
subcommand, the files arc keeps, the configuration, and the exit codes.

## Fixes

- **`git commit` works in the Linux `workspace` sandbox.** The Linux sandbox
  made all of `.git` read-only, so a commit in the `workspace` tier always
  failed. `.git` is now writable except `config`, `hooks` and the worktree
  pointer files, the same as on macOS. A submodule or worktree that is created
  during a session does not get this protection for its own `config` and
  `hooks` on Linux; `crates/radian-sandbox/LIMITS.md` lists it.
- **`!` and `!!` read the trust decision once, at session start**, like the
  `shell` tool. Before, `/trust on` stopped the git safety keys for `!` at
  once but not for the `shell` tool. `/trust` changes the saved decision; the
  session uses it from the next start.

## MCP servers can set `cwd`

- An MCP server entry accepts `cwd` in every place an entry is read:
  `--mcp-config`, the `[mcp]` section of `config.toml`, and the project
  `.mcp.json`, in both the `servers` and the `mcpServers` forms.
- `${VAR}` and a leading `~` expand. A relative path resolves against the
  directory of the file that declares the entry, so `"cwd": "."` in a project
  `.mcp.json` is the project root.
- A `cwd` that is not an existing directory skips that one server with one
  warning; the other servers still start.

`docs/user/mcp.md` has the details.

## Manual

- `docs/user/permissions.md` lists the git safety keys that every command
  gets in an untrusted project (`GIT_CONFIG_*`: hooks off, filters emptied,
  diff drivers neutralized) and how trusting the project removes them.
- `docs/user/subagent-and-jobs.md` has a new section on how the shell runs a
  command: its own session, no controlling terminal, and a stop that signals
  the whole session. `job kill` and `/jobs kill` stop the job's whole session,
  not only its process group; the manual said process group before.

## Install

`brew upgrade radian` (or `brew install hisea/tap/radian`), a release
tarball (check it against its `.sha256`), or `cargo install` from source.
The manual is at <https://getrad.dev/docs/>.
