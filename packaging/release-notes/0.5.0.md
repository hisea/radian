# radian 0.5.0

This release adds `radian acp`, an Agent Client Protocol server, and lets a
custom provider find the wire protocol of each model by itself. arc gains
flows: named routes that pick a task's worker, gate profile and limits, and
its default worker is now `radian acp`.

## `radian acp`

- **`radian acp` serves radian to an editor over the Agent Client Protocol**
  (version 1, stdio), one session per process. It takes the same
  conversation flags as `radian exec`. `session/load` replays the session's
  journal and continues it. Permission requests and `ask_user` map to ACP
  requests. See `acp.md` (`radian docs acp`).

## Providers

- **A named provider resolves the protocol and the endpoint per model.**
  First a `[[providers.<name>.models]]` rule (`match`, `kind`), then the
  provider's model list (`endpoints[].api`, `supported_endpoint_types` or
  `native_endpoints`), then `kind`. `prefer` orders the protocols one entry
  offers, and `base_urls` overrides one protocol's endpoint. A table with
  only `models`, `prefer` or `base_urls` adds them to the `auth.json`
  provider of that name.
- **A refused protocol is probed and remembered.** When a request fails with
  HTTP 400, 404, 405, 415 or 422 before streaming, radian tries the other
  protocols (at most two extra attempts). The protocol that works is used for
  the rest of the turn and saved as a rule in `config.toml`. When every
  protocol fails, the error names each attempt and the rule to set.
- **New kind `openai-responses`** for a custom provider. pi's names
  `openai-completions` and `anthropic-messages` are accepted as aliases.
- **opencode-go:** chat and Responses use the `/inference/go/v1` base. The
  Go plan limit is a usage-limit error that names its window. Chat requests
  send the catalog's `max_tokens` and ask for usage in the stream.
- `RADIAN_EXTRA_BODY` merges a JSON object into every request body. The
  keys each adapter reserves are refused.
- Reasoning replay falls back to the bundled model catalog when no cached
  catalog exists.

## The agent

- **A truncated answer continues.** A response cut at the output token
  limit without tool calls gets a durable continuation notice, at most two in
  a row. After that the turn ends `Incomplete`.
- **Tool descriptions name only mounted tools.** With `--tools` or a
  `subagent` that mounts part of the tool set, the `shell`, `job` and
  `subagent` descriptions no longer point at tools that are not there. With
  the full set the text is unchanged.
- An absolute path inside the workspace is a workspace path in every tier.
- A shell stop (timeout, `esc`, `job kill`) sends SIGTERM to the command's
  whole session, then SIGKILL after 3 seconds. It also reaches children that
  started a session of their own (`apt-get`'s `dpkg`).
- `radian exec --output jsonl`: the `Result` record carries `model_error`
  (`kind`, `status`, `retry_after_secs`) when a turn failed on a model error.

## arc

- **Flows.** `[flows.<name>]` picks a task's worker (the radian worker, a
  command, or an ACP agent), its gate profile, its `before_attempt` commands,
  its concurrency, and its defaults for `allow_noop` and `commit_dirty`. The
  TUI shows a task's flow, its waiting reason and the running count per
  flow. See `docs/user/arc/flows.md`.
- **The radian worker runs `radian acp`.** A cancel is recorded with the
  interrupted prefix.
- **An unavailable model waits instead of failing.** A review or a worker
  whose model is unavailable or out of its plan window waits until
  `retry_at`, then reverifies or retries by itself without using a retry.
- A command worker's stdout shows in the task's conversation tab.
- arc's own fetches into a repository take turns on one lock.
- A gate start is counted once, and a started gate keeps the profile it ran
  under through the merge.
