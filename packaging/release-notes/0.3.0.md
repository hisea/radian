# radian 0.3.0

This release adds image input, a read-only terminal interface for arc, and a
review stage in the arc gate. arc also runs without waiting for its workers,
reworks a task by itself when the gate fails, and can cancel a whole plan.

## Images

- A PNG, JPEG, GIF or WebP file reaches the model as an image from four
  places: the `read` tool, an `@path` reference in your message, a file you
  drop onto the terminal, and `radian exec --image <path>`. The format is
  judged by the file's magic number, not its extension.
- The transcript shows `[image: <file name>, W×H, N KB]`. Backspace on an
  empty input removes the newest attachment. An image over a size limit
  makes the message unsendable and names the limit.
- The context estimate counts an image by its pixels, not its bytes, and
  compaction folds an image to a placeholder.
- Every provider route sends an image in a user message. `docs/user/tools.md`
  lists which routes deliver an image in a `read` tool result.

## arc

- **`radian arc` opens a read-only interface.** The plans page lists every
  plan with its tasks, marks, attempts and cost. The task page shows the
  selected attempt's worker conversation, the task's diff, and each attempt's
  gate verdicts. It reads the store every 2 seconds and writes no arc state.
  The merge page and the owner's actions are not built yet.
- **A review stage.** A gate profile can list `review`: a read-only `radian
  exec` session reviews the task's diff against its brief and lists blocking
  items and suggestions; an item can carry a level, `critical`, `major` or
  `minor`. A rework round reviews only the
  rework, and an item on a line the rework did not change does not fail it.
  The `commands` and `review` stages run at the same time.
- **arc reworks a task by itself.** A review that fails writes a rework brief
  from its items. A conflict with main writes a "resolve the conflict" brief.
  A command failure is verified again once main moves. Each has its own
  limit, so a task that keeps failing stops and waits for you.
- **Every attempt starts on current main** (`before_attempt =
  ["merge-main"]`), and by default a rework starts a fresh worker session
  with a short hand-off instead of the old context
  (`[worker] rework_session`, `fresh` or `resume`).
- **`max_attempts` counts retries only.** A rework resets the count, so a
  task that the review sends back many times is not exhausted.
  `[limits] max_conflict_rework` (default `3`) bounds a run of conflict
  reworks.
- **`radian arc run` does not wait.** A pass starts workers and gates as
  separate processes and returns; `--watch` repeats it. Ctrl-C stops only the
  loop. A gate that keeps dying is recorded as `died` after
  `[limits] max_gate_deaths` restarts (default `2`), and `radian arc reverify`
  re-runs a gate that is stuck or was wrong, without a worker.
- **New commands and fields:** `radian arc priority <PLAN> P0..P5` sets the
  order in which the loop serves plans. `radian arc cancel <PLAN>` stops a
  whole plan and marks it `cancelled`. Plan and task ids have a kind prefix
  (`PL0001`, `TK0001`). `radian arc list` hides finished work unless `--all`.
  Items the review left unfixed become a proposed task, which you confirm
  with `radian arc confirm <TASK>`.

`docs/user/arc.md`, `arc-gate.md` and `arc-files.md` (or `radian docs arc`)
are the full reference.

## Other changes

- `write` creates missing parent directories inside the workspace.
- The `shell` tool's notes about a clamped timeout or clamped output appear
  with the exit code, not after the error output.
- The `job` tool never asks for approval.
- `/model` refreshes every listed provider's model list from that provider's
  own base URL, and never sends a model-list key over plain `http` to a
  remote host.
- The patch card shows the diff of the `edits` form, and a failed call shows
  its error text instead of a diff it never applied.
