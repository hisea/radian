# radian-host

Host plumbing that `radian-exec` and `radian-tui` both need, kept in one place so the two hosts
cannot drift. It is the part of a host that is the same whether the user is at a line prompt or
in a full-screen UI: `--header` parsing, session-id generation and validation, the
`--mcp-config` file, model construction, the startup description of the permission tier, and the
"built-in tools + MCP servers" provider.

It does **not** know about a terminal, a prompt loop, a session directory or a flag parser. The
two binaries still own their own flags, their key lookup, their startup text layout and their
error wording. Nothing here reads the environment for an API key, opens a session file, or
decides a permission.

## Model construction

`radian_core::Model::complete` returns `impl Future` (RPITIT), so `Model` is **not object safe**
and a host cannot hold a `Box<dyn Model>`. `HostModel` is therefore an enum
(`OpenAi` / `Anthropic` / `ChatGpt` / `Responses`) that implements `Model` by matching on its
variant: every protocol lives behind one type with static dispatch. `ChatGpt` is the OAuth
Responses route (ADR 0026); `Responses` is the API-key Responses route (ADR 0026
).

`build_model(ModelArgs) -> Result<HostModel, String>` turns resolved values into an adapter.
`ModelArgs` is everything the host resolved beforehand: `provider`, `base_url`, `model`,
`api_key: Option<String>`, `headers`, `include_usage: Option<bool>` (OpenAI-compatible only),
`max_tokens` and `thinking` (Anthropic only), `max_output_tokens` (the catalog cap sent as the
chat route's `max_tokens`, ADR 0018), `reasoning_effort` / `reasoning_replay`, and
`chatgpt_oauth`. `Provider` is `OpenAiCompatible`, `Anthropic` or `ChatGpt`, with `from_name`,
`as_str` (the name written into the session's config snapshot) and `default_base_url`.
`route_output(adapter, base_url, max_tokens)` and `RouteOutput` say what the request sends
(Anthropic's `max_tokens`, the chat catalog cap, or none); `RouteContext::output_for` resolves
the same value for a switched route. `default_include_usage(provider)` says which descriptors
ask for streamed usage by default (`opencode-go` does; every other provider keeps the
adapter's host rule, `api.openai.com` only).

### The wire protocol comes from the catalog (ADR 0026)

- `Protocol` is `OpenAiCompatible | Anthropic | Responses`. `Protocol::from_npm` maps
  models.dev's `@ai-sdk/openai-compatible` / `@ai-sdk/anthropic` / `@ai-sdk/openai` to them; any
  other value is refused with `unsupported_api_message` ("radian does not support this model's
  API (<npm>)"), never silently sent as chat.
- `ProviderRef::resolve_protocol(catalog, model)` takes a **built-in** descriptor's model
  protocol from the catalog entry's `npm` (entry-level `provider.npm`, else the provider-level
  `npm`); a model the catalog does not carry uses the built-in table (`descriptor.protocol_for`).
  Named/custom providers (D10) and the generic `openai-compatible` descriptor are untouched
  (decision 5).
- The endpoint is **not** from the catalog: `ProviderRef::endpoint_for(protocol, _)` and
  `descriptor_base_url(id, protocol)` give the hard-coded per-(descriptor, protocol) base, so a
  one-line catalog change cannot redirect a request that carries the user's key (decision 2). A
  credential entry's `RADIAN_BASE_URL` still overrides it (the existing escape hatch).
- `catalog::protocol_catalog()` is what a host hands `resolve_route_for`: the local cache when it
  parses, else the **bundled snapshot** compiled in with `include_str!`
  (`src/catalog-snapshot.json`, `SNAPSHOT_DATE`), regenerated by
  `scripts/update-catalog-snapshot.py`. `Route::protocol_notice` is `Some("protocol from
  models.dev")` when the catalog overruled the table, for the startup line.
- The same snapshot keeps each model's `modalities.input`. `catalog::route_takes_images(provider,
  model)` answers the `read` tool's per-call image capability from the warm cache (else the
  snapshot), parsed once per process: `Some(false)` only when the entry names its input
  modalities and they lack `image`; a missing model or a missing `modalities` counts as taking
  images. `open_session` hands `CodingTools::with_image_support` a closure over the live route,
  so a `/model` switch changes the answer without reopening the session.

`Thinking` is the `--thinking` value: `Off` (the default; sends **no** `thinking` key, so the
request is byte-identical to the pre-thinking adapter), `Adaptive`, `Enabled { budget_tokens }`.
It implements `FromStr` for `off` / `adaptive` / `enabled:<budget>`.

`check_provider_flags(provider, thinking, max_tokens)` refuses `--thinking` and `--max-tokens`
under `openai-compatible`, where they would be silently ignored. The hosts pass the **raw** flag
values, so "the user did not pass `--max-tokens`" is distinguishable from "the user passed the
default". `build_model` additionally checks Anthropic's documented manual-thinking range
(`MIN_THINKING_BUDGET` ≤ `budget_tokens` < `max_tokens`) **before any session file exists**,
because the adapter itself does not validate it locally (wire notes §2.3).
`DEFAULT_MAX_TOKENS` (16384) is the `max_tokens` sent when the flag is absent: the Messages API
requires the field and defines no server-side default.

`redact_base_url(raw)` is this crate's name for the provider crates' URL redaction, so both hosts
redact identically in an error that names the configured endpoint (ADR 0013 T4).

## The combined tool provider

`HostTools::new(coding: Option<CodingTools>, mcp: McpToolProvider)` is one `ToolProvider`,
so `Agent` still has a single provider type. `open_session()` opens the MCP servers **first** (if
that fails, no built-in state needs unwinding), then the built-in tools, then merges the specs
with `merge_tool_specs(built_in, mcp)`. `HostSession::execute` routes a call to the built-in
session when the name is a built-in one, else to MCP; `close()` shuts the background jobs
down (ADR 0037 decision 6) and then closes the MCP session.

### Background jobs (ADR 0037)

The host creates the `radian_coding::Jobs` registry (from the canonical workspace root) and
passes it to `CodingTools::with_jobs`, so it can subscribe to job lifecycle notices.
`job_notify::JobNotifier` writes the non-critical `BackgroundJobStarted` /`BackgroundJobSettled`
records and sends **one System message** per notifiable settle: while a turn is in flight it
`inject`s (`next_step`, no wake), and while the driver is idle it `followup`s (`next_turn`,
which wakes a turn). After `MAX_CONSECUTIVE_WAKES` (3) wake-started turns with no user input it
degrades to `inject` only; a user message (`SessionCommand::SendFollowup`/`Steer`/`Inject`)
resets the budget. A settle is not notified when the model already has it (a `job` wait, a
`job` kill, a session-exit cleanup); a timeout is notified. On resume, a
`BackgroundJobStarted` with no settle is injected once as unknown and never re-run. The registry
also kills every running group on `close()` and on drop (the panic path, `killpg` only).

### Subagent (ADR 0043 decision 2)

`subagent { agent?, task }` runs one task in a **fresh, blocking child `radian exec`** — the
current executable, so there is only one binary (ADR 0032) — and returns its last assistant text
(its journal, cut at 4 000 characters with a visible marker), the child session id and the usage
and denials its journal recorded. `explore` mounts only `read glob grep`;
`general` (the default) mounts the child's ordinary headless set, which is this session's tools
minus `subagent`. `explore` runs on the user-level `[model.smol]` route (`provider` and
`model`, the same meaning as the `[model]` route keys) when it is set, and otherwise follows
the parent exactly as `general` always does; a half-set table warns and is ignored, and a
project config never sets it.

The child gets the parent's **resolved** tier (`--profile` read from the live sandbox slot, so
`/access` is obeyed) and never a wider one, and `--yes` only while the parent's approval policy
is `auto`; otherwise the child has no terminal, so every `ask` is denied and the result names
what was denied. A `general` child always gets the parent's **live** route (`--provider` and
`--model` read from the same slot a `/model` switch lands in); an `explore` child gets the
`[model.smol]` route when one is configured. The tool is `Shared`: several calls in one reply are the parallelism. The
parent turn's cancellation kills the child's whole session through the same `kill_session` /
`signal_session` path the job supervisor uses. The depth is 1: `open_session` drops the launch
parts when the session's own `parent` relation is `"subagent"`, so a child never mounts
`subagent`. `subagent` is `allow` in every tier (it writes nothing itself; the child's own tier
and approval govern the work).

**Not promised:** a parent killed with `SIGKILL` can leave the child running (macOS has no
`PDEATHSIG`); the child's journal is on disk and `radian attach <id>` still reads it. `--header`
values are not forwarded to the child; a provider that needs a CLI-only header must be
configured in the config file instead.

## Headers, session ids, MCP config, workspace

| Item | Rule |
|---|---|
| `parse_headers(raw, session_id)` / `SESSION_PLACEHOLDER` | Repeated `NAME=VALUE`; `{session_id}` in a value expands to the process's session id. A malformed argument, an empty or non-token name, and `authorization` all fail. **The value of a failing argument is never part of the error** — a user who forgot the `=` may have pasted a credential as the whole argument. The name may be echoed. |
| `generate_session_id()` | `{nanos:x}-{pid:x}`. Stable within a process, different across processes; no UUID dependency. |
| `validate_session_id(id)` | A session id becomes a file name: 1–128 characters of `[A-Za-z0-9._-]`, and not `.` or `..`. |
| `load_mcp_config(path)` | The `--mcp-config` file into `McpServerConfig`s. Unknown fields are rejected (`deny_unknown_fields`), so a typo cannot silently drop a setting, and duplicate server ids fail **before any process starts** — the id prefixes every tool alias. |
| `resolve_workspace(workspace)` | `None` means the current directory. The path must exist, be a directory, be **readable** (`read_dir`, which is what mounting tools there actually needs) and canonicalize. The messages never mention the sandbox or a `full-access` fallback, so a mistyped path fails as a workspace problem, before the sandbox probe and before any session file exists (dogfooding D1/D2). |

## Memory (ADR 0021 D1/D2/D8)

`radian_host::memory` is the host side of the memory system. It never reads `HOME` (the caller
passes the root), never touches the network and never starts a process.

`MemoryWriteGuard` (ADR 0021 invariant 4) is the host decision in front of `write` and
`patch`, mounted by `open_session` whenever memory is on. It refuses a call whose canonical
target is a scope directory in two cases: this session has taken in an MCP tool result (the
input guard; a resumed session counts a settled call to a tool an MCP server provided in its
committed journal — a name no server provides settles `unknown_tool` and does not count), or the
content — for `patch`, the content the edit would produce and each inserted replacement —
matches the ADR 0008 §3.2 rule-2 secret heuristic, naming the prefix and never the value.
The permission profile's memory rule is separate and unchanged: these guards can only refuse
a write the tools would otherwise allow, never grant one.

`project_identity_key(workspace)` is pure Rust and returns the **git common dir** of the
repository containing the workspace, so all worktrees of one repository share a `ProjectId`;
outside a repository it returns the workspace's canonical path. A `.git` **directory** is the
common dir itself; a `.git` **file** is resolved through its `gitdir:` pointer and then
`<gitdir>/commondir` (falling back to the documented `<common>/worktrees/<name>` layout), and
the result is canonicalized. A pointer that cannot be resolved falls back to the workspace.

`MemoryService::open(workspace, root)` owns the `MemoryStore`, the `ProjectRegistry` and the
workspace's project resolution. Its API is **synchronous** (the store is a single-writer JSONL
log; every operation is short, and both hosts call it where blocking on an fsync is fine).
`state()` returns `ProjectState::{Known, Unlinked { identity_key, candidates }}` and **never
registers**. `project_for_write()` is the **write** path that may register (ADR 0021):
a git workspace whose identity key is not in the registry is registered now and returned as
`ProjectForWrite::Created`, whose `notice()` is the one line the hosts show (with the
`relink`/`merge` hint when a repository of the same name is already a project); a key that is
not a git common dir is the `NotAProjectWorkspace` error ("not a project workspace … the memory
was not saved", pointing at `radian memory project new` and at no other scope). **Reads and
injection never call it**, so they only ever read Global on an unregistered workspace.
`create_project()` and `relink()` stay the explicit routes. Reads default to Project then Global
(`ScopeSelection::Default`); writes default to Project (`WriteScope::Project`). Every user
command is `Source::User`.

`file_tool_roots()` names the two scope directories the file tools may read and write in both
tiers (ADR 0039 decision 4): `<root>/global/` and, when `state()` is `Known`,
`<root>/projects/<ProjectId>/`. It resolves through `state()`, so a read never registers a
project; an unlinked workspace gets the global directory only. Each directory is created 0700
on first use (ADR 0021 D3).

`candidate_name` is the comparison behind "同名仓库": the identity key's final path component,
except that a git common dir (`.git`) is named by its parent directory — the repository name —
so a moved repository still matches its old project.

### Memory index injection (ADR 0021 D6)

The model has no memory tool. `memory/injection.rs` reads each scope's `MEMORY.md` through
the file store at the first model call: the project scope (when the workspace maps to a
project; reads never create one, D2) then global. `MemoryHooks` appends one fixed section to
the system prompt: the low-trust header, `## Project memory index`, one line naming the file
and the index text, then `## Global memory index` likewise. A missing or empty index
contributes one line; an index that cannot be read contributes one line and one warning
naming the file, never a failed turn (invariant 2). `[memory] index_max_lines` (default 200)
and `index_max_bytes` (default 25600) cap each index, keeping whole lines; a dropped line
sends one `System`-source rewrite notice on the inbox's inject lane before the next call,
once per session per scope. `MemoryInjection` computes the section once per process and
reuses it byte for byte (ADR 0036): an index change reaches the prompt at the next session or
resume. Before an index is capped it is neutralized: every Unicode default-ignorable code
point is removed, and a line that begins with `<system`, `</system`, `<project_instructions`,
`</project_instructions`, `<memory` or `</memory` (case-insensitive, leading whitespace
allowed) gains a leading `\`. The file on disk is never changed. When the section is built,
the hook writes one `critical: false` `MemoryInjected` record naming each injected index
(path, sha256 of the capped neutralized text, lines, bytes).
`[memory] enabled` (default true) and `[memory] scopes` (default both, in project-then-global
order) select it. Every `[memory.injection]` key is retired: it gets one migration warning
naming it and the index caps, and is otherwise ignored.

## The startup description

`describe(mode, sandbox, wording) -> (String, String)` returns the two startup lines: what was
chosen, and what it actually means. The two hosts keep only the phrases that are honestly
different, in `Wording`: `CLI_WORDING` ("commands and built-in tools")
and `TUI_WORDING` ("shell and the built-in tools"). Everything else — including the sentence
that must **not** be weakened, "MCP servers are NOT sandboxed" (ADR 0012 P6) — is
written once here.

`sandbox_word(mode, backend)` is the TUI startup summary's word for the sandbox (ADR 0027). For
`workspace` it names the real backend in plain words — `macOS sandbox` for `macos-seatbelt`,
`Linux sandbox` for `linux-bwrap`, and the backend's own name for one this build does not know —
so a summary can never be read as "no sandbox"; the exact backend name stays in the expanded
`profile:` line. `full` is `no sandbox · no prompts` (the built-in default since ADR 0043). A missing backend in an enforced mode is
`sandbox missing`, never `none`.

The `workspace` line says `sandbox on: commands stay in the workspace` (ADR 0043 decision 2.4);
`full`'s line is `full · no sandbox · no prompts`, with the "no sandbox … · no prompts"
sentence as its facts line.

## The project declaration

`project::read(workspace)` reads `<workspace>/.radian/config.toml` (ADR 0043 decision 2). The
only key it uses is `[permissions] profile = "workspace"`; `full` there is a warning
and is ignored, any other key is skipped and named, and `[sandbox]` keys (`allow_env`,
`allow_unix_sockets`) are refused by name because the user-level configuration owns them
(ADR 0034). `project::narrow` / `project::effective` return the narrower
of two tiers (`workspace` < `full`): a project can turn the sandbox on and can never
turn it off. The file's presence also counts as a project resource for the trust gate.

## Known limits and what is not verified

- **This crate has no integration tests.** Every guarantee above is a unit test in the module,
  or a test in `radian-exec` / `radian-tui`. A change here that only the hosts exercise is caught
  only when those suites run.
- **`describe` is wording, not enforcement.** It reports what was chosen; it cannot check that
  the sandbox was actually built. The unreachable `(WorkspaceWrite, None)` arm says so in its
  own text ("the sandbox is missing; this must not happen").
- **`check_provider_flags` only knows the two providers that exist.** Adding a third provider
  means revisiting it, because its whole job is "which flags would be silently ignored".
- **The manual-thinking range is checked here, not in the adapter.** A caller that builds
  `AnthropicConfig` directly bypasses `MIN_THINKING_BUDGET`; the wire notes record that the
  adapter deliberately leaves the range to the server.
- **`HostModel` is an enum, not a trait object.** A third provider is a third variant and a
  match arm in `Model::complete` — the reason is the non-object-safe `Model` trait, not a
  preference.
- **The catalog decides a built-in descriptor's protocol, not the endpoint.** `provider.npm` is
  the only field read for it (ADR 0026); `provider.api` is not even parsed. An `npm`
  with no adapter is refused, so a catalog entry for a new protocol disables the model until
  radian gains that adapter.
- **The bundled snapshot is a release artifact.** `src/catalog-snapshot.json` is regenerated by
  `scripts/update-catalog-snapshot.py` before a release (never from a test or the binary); a
  snapshot older than the constants is caught by `the_bundled_snapshot_parses_with_its_date`.
- **`HostSession::close` closes the MCP session only.** The built-in `CodingSession` holds no
  resources and uses the trait's default `close`.
- **`load_mcp_config` reads a JSON file and nothing else** — no TOML, no merge with another
  source, and unknown fields are an error rather than a warning.
- **The credential store has no write lock (ADR 0026 D1).** `auth::upsert_api_key` and
  `auth::remove` read-modify-write `~/.radian/credentials/auth.json` without a lock, so two
  `/login` runs at once race: the later write wins and may drop the earlier provider's entry.
  Accepted for the first release.
- **Not verified here:** Windows, real provider endpoints, and the sandbox itself. The MCP
  processes this crate helps start are **not** sandboxed in this build (ADR 0012), and the
  startup notice that says so is pinned by the two host tests above.
