# 压缩后重读：摘要丢掉文件内容，模型只能重新读

- 状态：decided（2026-10-31，方向 1；设计点：按 token 预算，同一路径只留最新一次）
- 涉及 ADR：0018（§摘要、保留尾部 K、回退步骤）、0015（估算）
- 来源：2026-10-31 Mac 轮（deepseek-v4.1-flash，`--context-window 128000`，B = 96k，二进制 6b94155be）

## 现象

4 个短任务 × 2 个 128k 臂 × k=2，共 25 次压缩，0 次 below_target、0 次回退。压缩后 5 步内的 53 次 `read` 里 46 次读的是压缩前已经读过的路径；25 次压缩有 12 次超过预先登记的"≤2 次重读"线。同一任务 128k 臂的模型调用数是 1M 臂的 1.3–2.2 倍，费用约 1.3 倍，尽管 prompt 更小（1M 线路缓存命中高）。摘要提示里已经有 "Files read and modified（每个文件）" 和 "Verified facts (do not re-check)" 两节：路径清单没有阻止重读，模型要改文件就得要内容。

## 决定

压缩时，保留尾部之外再保留**最近读过的文件内容**：

- 单位是 ADR 0018 的 unit（含 `read` 调用的助手消息 + 它的工具结果）。从切点往前走，遇到 `read` 调用取其 `path`；同一路径只取最新的一次（oh-my-pi 的 supersede 规则），更早的同路径 read 不保留。
- 预算：`⌊K/2⌋` token（ADR 0015 估算），从 K 之外另算还是从 K 里分，由实现按 ADR 0018 的预算算式定并写进 ADR；32k 窗口下 K = 6144，预算 3072，装不下就一个都不留，行为与今天一致。
- 一个 unit 装不下预算剩余就跳过它，继续看更早的（更小的可能装得下）；不截断 read 结果。错误结果（`is_error`）不保留。
- 保留的 unit 原样放在摘要消息之后、保留尾部之前，按时间顺序；两个 provider 的请求都合法（contract suites）。它们不受回退步骤 ① 的 2000 字符截断（否则白留）。
- 摘要器的输入不变（它仍然看到被摘要的全部内容）。
- `ContextCompacted` 记录保留了哪些 unit（数量和路径）；事件形状变了就同步 `docs/schema` 的 fixture。
- 其余方向：2 不做（清单已证明无效）；3 异步压缩另开 item，等本项数据；4 已落地（ADR 0018：chat 输出预留改为 15% 窗口份额）。

## 边界情况

- 同一路径两次 read 不同 range：按路径取最新一次，不合并。
- 最新一次 read 本来就在保留尾部里：不重复保留。
- 最新一次 read 超预算、更早一次能装下：跳过最新的也不要更早的（它已被更新的读取取代）。
- 预算用完一半时剩下的都装不下：留已选的，不补小的。
- 1M 窗口不压缩：行为不变。
- 第二次压缩：上一次保留的 read unit 现在在被摘要区里，和别的 unit 一样重新参与选择。

## 验收

- compaction_flow 测试：三个路径各读两次 → 保留三个最新 unit；预算只够两个 → 最旧路径的不留；同路径最新的超预算 → 该路径不留；错误结果不留；32k 预算 3072 装不下 → 零保留且不失败；保留的 unit 不被步骤 ① 截断；两次压缩后不重复。
- 变异：去重去掉（同路径两次都留）→ 测试失败；预算检查去掉 → 失败；保留 unit 被步骤 ① 截断 → 失败。
- 复跑：128k 两臂 × 4 短任务 × k=2（约 $1.5），压缩后 5 步内重读压缩前路径 ≤ 2 次；调用数相对 1M 臂的比值下降；checks/review 不更差。`benchmarks/journal_metrics.py` 加一列 `rereads_after_compaction`（压缩后 5 步内重读压缩前路径的 read 次数），报告直接读它。
