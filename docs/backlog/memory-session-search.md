# 过去的会话当记忆：模型可以查「上次我们怎么做的」

- 状态：idea
- 涉及 ADR：0021（记忆与会话的边界）、0006（会话 JSONL）、0019（只读已提交的会话事实）、0043（单会话）
- 来源：对手调查 2026-10-31（Amp、Codex）

## 背景

Amp 让模型搜索过去的线程，包括工作区成员的线程，提到一个线程就读取并提取相关内容；Codex 的离线提炼给每个 rollout 生成 `rollout_summary` 与 `rollout_slug`，等于一份会话索引，模型通过记忆工具读它。radian 的会话全文搜索只在 TUI 的会话列表里给人用（`docs/user/sessions.md`），模型没有任何工具回答「上次我们怎么做的」；记忆文件（`memory-files.md`）存的是提炼后的结论，不是过程。

## 待决问题

- 模型侧是一个 `sessions_search` 工具（关键词查本工作区的会话，返回会话 id、时间、首条用户消息、命中片段），还是每个会话结束时宿主写一行摘要进一个只读的会话索引文件，由模型用 `read` 按需读。
- 只读已提交的会话事实（ADR 0019），当前进程打开的会话排除。
- 结果是低可信数据（不变量 4 的同一条规则）；跨工作区的会话不可见（`sessions.md` 的现有规则）。
- 工具还是文件，取决于 `memory-files.md` 落地后索引的读法：如果记忆已经是「索引注入、正文按需读」，会话索引用同一条路最省。

## 验收（落地时）

- 模型在新会话里能定位到一周前处理过同一文件的会话并读到那段对话；当前进程打开的会话不出现在结果里；另一个工作区的会话不出现。
