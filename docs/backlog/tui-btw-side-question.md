# `/btw <问题>`：旁路提问，用当前上下文回答，不进 transcript

- 状态：decided＼�第一档）
- 涉及 ADR：0010（live 与 durable）、0018（缓存前缀）、0023（层栈 U4）、0007（usage 记录）、0017（错误只影响自己）
- 来源：`docs/research/2026-10-20-peer-slash-commands.md` §2.1、§3 第一档

## 背景

用户常想问「刚才那个配置文件叫什么」「你为什么选 B」，今天只能发成一条正式消息，污染历史还打断回合。Claude Code 的 `/btw`、Codex 的 `/side`、omp 的 `/btw`、pi-btw 扩展都是这个功能，形状不同（见来源 §2.1）。radian 取 Claude Code 的形状：一次额外请求、不带工具执行、只在屏幕上。

## 决定（已定）

- 请求形状：走会话当前的模型路由与 thinking 设置（不换模型、不关 thinking，否则 Anthropic 的消息前缀缓存失效），system prompt、工具定义、有效历史（压缩后的视图）与下一次正式请求**完全相同**，最后追加一条用户消息：问题，加一句固定说明「只根据已有上下文回答，不要调用工具」。前缀相同所以缓存命中（ADR 0018）。
- 不执行工具：模型若仍返回工具调用，不执行，答案末尾加一行「未执行任何工具」。权限层不介入，因为没有工具跑。
- 只在屏幕上：答案在一个覆盖层里流式显示（ADR 0023 U4 的一层，和会话选择器同级）；不写 transcript，不写 journal，不发 durable 事件（ADR 0010 K1 live）。
- 并发：回合进行中允许发 `/btw`，主回合不受影响；同一时间只允许一个旁路请求，第二个 `/btw` 以通知拒绝（omp 同）。Esc 取消在飞的旁路请求或关闭覆盖层；`/btw` 不带问题重新打开最近一次答案。
- 每个问题独立，不回放之前的旁路问答（Claude Code 回放 20 条，留作以后）。本进程内保留已完成的旁路问答供覆盖层翻看，退出即丢。
- usage：覆盖层最后一行显示这次请求的 token 与费用；**不**计入会话总计，**不**写 `ModelUsage` 记录（ADR 0007 J5 要求紧跟 assistant 消息，这里没有）。
- 旁路请求出错只在覆盖层显示，不触发 ADR 0017 的回合失败路径。
- 只有 TUI 有；`radian exec` 没有。

## 验收

- mock provider：`/btw q` 的请求体 = 下一次正式请求体 + 末尾一条用户消息；transcript 与 journal 字节不变（`journal-selfcheck` 绿）。
- 回合进行中 `/btw` 不影响该回合的请求数与结果；第二个 `/btw` 被拒绝。
- 模型返回工具调用时没有任何工具执行且覆盖层有说明。
- Esc 取消在飞请求后，主回合继续正常结束。
