# `ask_user`：保留，瘦身定义，把"什么时候问"写进工具描述

- 状态：decided＼�保留并优化）
- 涉及 ADR：0024（问题形状；本项不改字段形状则不动）、0036（角色规则里已有"先查再问"）
- 来源：本机 radian 会话统计（2026-10-20）；`docs/research/2026-10-14-system-prompts.md` "什么时候问用户"一行

## 背景（已核实）

- 用量：本机 158 个会话、14,658 次工具调用里 `ask_user` 16 次（11 个会话，约 0.1%）；只在 TUI 挂载，`radian exec` 与无人值守不注册（ADR 0024 Q5）。一半以上是用户直接输入 `ask_user` 试工具；真正该由用户定的约 4 次（Terminal-Bench 先冒烟还是全量、"我所有的 block"指哪种、integration worktree 是否释放、一个查航班问题的处理方式）；也有误用：问用户"要读哪些文件""改完跑哪些验证"——这些模型该自己查，系统提示词里"先在代码里找答案，只问该由用户决定的事"没有拦住。
- 定义大小：约 2 KB（研究报告实测 1,988 B）。描述（`crates/radian-coding/src/ask.rs` `spec()`）与 schema 字段说明有重复：`header` 的"两三个词、作 tab 标签"、`recommended` 的"至多一个"在两处各写一次；"Only available when an interactive user is present" 对模型无用（没有交互用户时根本不挂载）。
- 同类做法：Claude Code 内建 `AskUserQuestion`；omp 内建 `ask`，`ask.md` 写"只在有实质不同、必须由用户决定的取舍时才问；默认根据代码、配置、文档、历史和惯例自己做"，并要求破坏性操作前先问；dsh 只在 plan 模式开放 `ask_user_question`，"只问用户拥有的选择或查不出来的实质歧义，能自己查到的（代码在哪、现在怎么工作）不要问"；pi 不内建（`question` 是随包扩展示例）。opencode、Codex 研究报告未覆盖（未核实）。各家都是模型调用工具、宿主弹表单，没有宿主主动触发；无人值守都不弹。

## 决定（已定）

1. 保留 `ask_user`，不加 plan 模式，不改问题的字段形状（不动 ADR 0024 Q2）。
2. 调用条件写进工具描述本身（omp/dsh 的写法）：只问必须由用户决定的取舍或查不出来的实质歧义；能从代码、配置、文档、历史查到的（读哪些文件、跑哪些检查、代码在哪）不要问；问时给出自己的推荐（`recommended`）。
3. 瘦身：去掉描述与字段说明之间的重复和对模型无用的句子，约束留在 schema（`maxItems`/`maxLength` 等），目标约 1 KB（值由落地时实测）。
4. 时机：并进"工具重构全部进 main 之后"的那次工具描述审查一起做；也可以单独先做，不冲突。

## 验收

- 用请求捕获实测 `ask_user` 定义大小，达到目标并写进报告。
- 描述里有决定 2 的规则；`prompt.rs`/工具描述测试钉住关键句（例如"do not ask what you can find"一类），变异：删掉这句 → 测试失败。
- `radian-tui` 现有 ask 的 pty/表单测试全过；字段形状不变。
