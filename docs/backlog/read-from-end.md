# `read` 从文件末尾读

- 状态：idea＼�先记下，不排期）
- 涉及 ADR：0039（`read` 的读根与安全打开不变）、0043 §4（工具描述的字节上限）
- 来源：2026-10-20 白天 dogfood 复盘（lead）

## 背景（已核实）

- `read` 的参数是 `path`、`offset`（从 1 开始，`minimum: 1`）、`limit`、`max_bytes`（`crates/radian-coding/src/read.rs`）。没有"从末尾数"的写法：要看一个文件的最后 N 行，模型得先知道总行数。
- 2026-10-20 白天 Mac 上 5 个 dogfood 会话里，读源码的 shell 调用共 65 次，其中 6 次是 `tail -N <源文件>`，3 次用 `grep -c ""` 数行数来找文件末尾。这 9 次是内置工具做不到、只能走 shell 的；其余读源码的 shell 调用 `read`/`grep` 都能做（`limit`、`max_matches`、同一回复里并行调用），属于模型习惯。
- 走 shell 的读取不会被识别为"同一文件的再次读取"，`context-pruning.md` 的"被新读取取代的先清"对它们无效。

## 待决方向

- (a) `offset` 允许负数：`-N` 表示从倒数第 N 行开始，`limit` 照旧。
- (b) 加一个 `tail: N` 参数，与 `offset` 互斥。
- 两种都要在描述里加一句话，受 ADR 0043 §4 的描述字节上限约束；目录读取不适用。

## 验收（定了方向后）

- 一个 1000 行的文件，"最后 5 行"返回第 996–1000 行，带行号；超过文件长度时返回全文；空文件返回空。
- 变异：从末尾数错一位，测试必须失败。
