# 记忆的共享层：随仓库走的项目记忆，多机之间的私有记忆

- 状态：idea
- 涉及 ADR：0021（D1 scope、D2 项目身份）、0020（`~/.radian/` 目录表）、0031（项目信任：仓库内文件何时被装载）、0036（上下文文件）
- 来源：对手调查 2026-10-31（Gemini CLI、Copilot、Amp、Devin）

## 背景

Gemini CLI 分四层：全局 `~/.gemini/GEMINI.md`、仓库内共享的 `GEMINI.md`、子目录、私有项目目录；Copilot 的仓库级事实与协作者共享，用户偏好跟人走；Amp 的工作区成员线程互相可搜；Devin 的知识按组织、企业、个人分。radian 的记忆只有本机私有（`~/.radian/memory/`），仓库内共享的只有 AGENTS.md。owner 自己就在三台机器（Mac、LXC、Hai-PC）上跑 radian，私有记忆互不相通。

## 待决问题

- 要不要仓库内的共享层 `.radian/memory/`（随 git，走代码审查）。它和 AGENTS.md 的分工：AGENTS.md 是指令，共享记忆是事实与决定的索引？还是干脆说共享层就是 AGENTS.md 加 `docs/`，不另开。
- 仓库内的共享记忆按 ADR 0031 只在受信项目装载，而且是低可信数据，不是指令。
- 私有记忆跨机器：是同步目录（用户自己用 git 或同步盘管 `~/.radian/memory/`，radian 只需容忍并发写入），还是 radian 不管。倾向不管，只保证目录可以整个复制。
- 多人共享一个仓库时，模型写的记忆进不进共享层：倾向不进，模型只写私有层，共享层由人经 PR 放。

## 验收（落地时）

- 受信仓库里的 `.radian/memory/MEMORY.md` 在私有索引之前注入，标为共享与低可信；不受信仓库不装载。
- 两台机器各自复制同一个私有目录后，索引注入字节相同。
